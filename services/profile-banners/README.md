# Баннеры профиля LinkiGram: сервер и Telegram-бот модерации

Один процесс Node.js обслуживает API и Telegram-бота. Изображения хранятся **на диске сервера**.
Бот не публикует сообщения в каналы: карточки приходят владельцу/модераторам.

## Как это работает

1. Пользователь выбирает изображение в настройках баннеров LinkiGram.
2. Приложение подтверждает Telegram ID через inline-запрос к боту и получает токен.
3. Сервер принимает оригинал до 8 МБ в приватную папку. Он проверяет содержимое и делает только приватное JPEG-превью для модератора.
4. Бот отправляет карточку с кнопками **«Одобрить → WebP»**, **«Отклонить»**, **«Оригинал»**.
5. Только при одобрении оригинал конвертируется в **статичный WebP 1200×400** с центральной обрезкой. Метаданные исходника в опубликованный файл не переносятся. Качество начинается с 82; при необходимости снижается. Максимальный результат — 1 МБ; фактический размер зависит от картинки.
6. Только одобренный WebP становится доступен через публичное API. Оригинал и превью удаляются. При отклонении они тоже удаляются; старый одобренный баннер сохраняется до одобрения замены.

Принимаются **JPEG, PNG, WebP, GIF, AVIF, TIFF**. Из GIF, анимированных WebP и многостраничных файлов используется **первый кадр/страница**. HEIC/HEIF зависит от кодеков установленной сборки libvips; не считайте его гарантированно поддержанным. SVG, PDF, видео и повреждённые файлы не принимаются. Нельзя поддержать буквально любой формат; недоступный кодек или слишком сложное изображение дают понятную ошибку в приложении.

Растровая сигнатура и реальный декодер проверяются независимо от имени и MIME файла.
Загрузка файла с переименованным расширением `.jpg` не делает его допустимым изображением.

## 1. Создать бота

1. Откройте **@BotFather**, выполните `/newbot`, задайте имя и username.
2. Сохраните выданный токен в `BOT_TOKEN` на сервере. Не вставляйте настоящий токен в исходники, Git или скриншоты.
3. В @BotFather выполните **`/setinline`**, выберите этого бота и укажите, например, `Авторизация баннера LinkiGram`. Без inline-режима авторизация приложения не работает.
4. Напишите своему боту **`/start`**. Это нужно, чтобы бот мог отправлять вам карточки.
5. Используйте отдельного бота для этого сервиса. Не запускайте параллельно другой `getUpdates` или webhook для того же токена.

## 2. Узнать свой Telegram ID

Нужен **числовой Telegram ID**, не username и не номер телефона.
Если уже знаете ID — пропустите этот шаг.

После загрузки файлов установите зависимости и укажите пока только `BOT_TOKEN` в `.env`:

```sh
npm install --omit=dev
npm run bot-info
```

Отправьте `/start` своему боту. Команда выведет username бота и ID людей, написавших ему в личные сообщения. Найдите себя. Сам сервер во время `bot-info` должен быть остановлен. Если команда не увидела `/start`, запустите её ещё раз после отправки сообщения.

## 3. Настроить сервер

Для Wispbyte выберите **Node.js** и актуальную версию **Node.js 24**. Минимум для кода — Node.js 22.13 (`node:sqlite`). Node 18/20 не подходят. Имя сервера, например, `linkigram-banners`.

Загрузите содержимое этой папки в рабочую папку сервера: `package.json`, `pnpm-lock.yaml`, `.js`-файлы и `config.example.env`. `test/` не требуется для запуска. Не загружайте локальный `node_modules`: сервер установит библиотеки под свою ОС.

Скопируйте `config.example.env` в **`.env`** и заполните:

```dotenv
BOT_TOKEN=ТОКЕН_ОТ_BOTFATHER
ADMIN_IDS=ВАШ_ЧИСЛОВОЙ_ID
ADMIN_CHAT_ID=ВАШ_ЧИСЛОВОЙ_ID
PUBLIC_BASE_URL=https://ВАШ_ДОМЕН_БАННЕРОВ
PORT=ВЫДЕЛЕННЫЙ_ПОРТ
DATA_DIR=./data
MAX_STORAGE_MB=600
MAX_PENDING=50
```

`ADMIN_IDS` может содержать несколько ID через запятую. Только они вправе одобрять/отклонять. `ADMIN_CHAT_ID` — чат для карточек; для личной модерации поставьте свой ID. Никогда не ставьте здесь чужой username.

Используйте порт, который выделила панель. Если платформа передаёт `SERVER_PORT`, можно убрать `PORT` из `.env`: сервер прочитает `SERVER_PORT`.

Нужен **публичный HTTPS-домен**, проксирующий запросы на этот порт. Сервер внутри контейнера слушает HTTP на `0.0.0.0`; TLS завершает платформа или обратный прокси. Один IP с HTTP-портом не подходит: Android-клиент скачивает баннеры по HTTPS.

`PUBLIC_BASE_URL` — только origin, **без `/api`, query или токена**, например `https://banners.example.org`. Доступность домена/HTTPS нужно отдельно настроить в панели хостинга.

Запуск:

```sh
npm install --omit=dev
npm start
```

Для установки строго по включённому lock-файлу вместо npm можно использовать:

```sh
pnpm install --prod --frozen-lockfile
pnpm start
```

Если панель сама устанавливает зависимости и просит только Startup File — укажите **`server.js`**. Если просит команду — `node server.js` (после установки зависимостей).

Проверка: `https://ВАШ_ДОМЕН_БАННЕРОВ/healthz` должен отвечать `{"ok":true}`.

## 4. Управлять модерацией

- Карточки новых заявок приходят в `ADMIN_CHAT_ID` автоматически. Если владелец ещё не нажал `/start` или Telegram недоступен, отправка повторяется раз в 20 секунд.
- **«Одобрить → WebP»** конвертирует и публикует баннер.
- **«Отклонить»** удаляет новый оригинал и превью. Ранее одобренный баннер не меняется.
- **«Оригинал»** отправляет модератору исходный файл документом.
- `/pending` — заново прислать необработанные заявки. При большом количестве карточки приходят постепенно.
- `/stats` — количество заявок по статусам.
- `/id` — ваш числовой Telegram ID.

Кнопки проверяют **ID нажавшего, чат и номер карточки**. Старые/повторные нажатия не публикуют файл повторно. После `/pending` используйте новую карточку.

Приложение опрашивает `/status/<id>` и показывает результат. У пользователя не обязательно должен быть открыт диалог с ботом для авторизации: приложение использует inline-запрос напрямую. Владелец бота должен открыть диалог для получения карточек.

## 5. Подключить Android-клиент

Изменения клиента в этой ветке уже добавляют WebP и загрузку произвольного исходного файла на модерацию. Но **домен сервера ещё не задан**.

В `private.properties` / GitHub Actions secret **`NIMARKO_BANNER_API_URL`** нужно поставить тот же HTTPS-origin, что и `PUBLIC_BASE_URL`, затем собрать клиент. `BOT_TOKEN` в APK не нужен и не должен туда попадать. Username бота приложение получает от API.

До настройки домена и новой сборки опубликованный APK 2.6.3 с этим сервером не считается подключённым. Ранее выпущенный APK также не содержит добавленную поддержку WebP баннеров.

## Ограничения для бесплатного сервера

- Оригинал до **8 МБ**, изображение до **32 мегапикселей**, опубликованный WebP до **1 МБ**.
- Не более одной ожидающей заявки на пользователя и пяти попыток загрузки в сутки на пользователя.
- По умолчанию до 50 ожидающих заявок и 600 МБ учтённых файлов. Остальное место оставляется для Node.js, SQLite, зависимостей и временных файлов. Если места мало, новые загрузки получают ошибку вместо переполнения диска.
- Тяжёлые операции идут последовательно, с ограничением времени; очереди и параллельные загрузки ограничены.
- Необработанные заявки удаляются через 7 дней и получают статус «отклонено». Их оригиналы не сохраняются бессрочно.
- Весь каталог `data/` должен находиться на постоянном диске. База, сессии, заявки и очередь бота сохраняются после перезапуска.
- Не запускайте два экземпляра сервера на одной базе. Резервную копию `data/` делайте при остановленном процессе, включая SQLite/WAL-файлы. `.env` храните отдельно и приватно.
- На бесплатном Wispbyte нужно соблюдать условие входа в панель, указанное в вашем тарифе.

## Проверки разработчика

```sh
npm test
```

Тесты используют временную базу и подменённый Telegram API: ничего не отправляют настоящим пользователям. Проверяются авторизация владельца, права модератора, отсутствие публикации до одобрения, удаление отклонённых оригиналов, конкурентные загрузки и конвертация основных форматов.

Документация библиотек: [Sharp](https://sharp.pixelplumbing.com/api-constructor/), [Telegram Bot API](https://core.telegram.org/bots/api), [Node SQLite](https://nodejs.org/api/sqlite.html).
